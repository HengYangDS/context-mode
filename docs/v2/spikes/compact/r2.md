## Step 2 root cause (empty UserPromptSubmit after compaction)

Evidence: Claude Code 2.1.303 PostToolUse payload for a 131,635 B Bash output (probe, raw payload kept in the
private run dir). `tool_response.stdout` is cut to 30,000 chars; the full output is only in
`tool_response.persistedOutputPath` (a tool-results file), with `persistedOutputSize` = 131635.
The hook journals and indexes `stdout` as given, so every compact-hard store holds a 30,000-char body
(checked in 4 live v2 stores: events seq 2 length = 30000, cut mid-line). 12 of 18 answers sit past byte
30,000 (log-fatal-req at 117,477, dist-hash-0417 at 42,813, ...). For those the prompt terms (a path, a size)
match no stored line, every BM25 score is under RECALL_MIN_SCORE, and recall returns "" (empty hook output).
Offline, with the whole output, a-ledger pickRecall holds the answer for 11 of 12 main questions.
This is also why the round 1 replacement chunks and ctx_search never had the values.
Fix: the claude-code decode reads the persisted file when the host cut stdout.

Note: v2-design 26cdd6df (D-M2-SHAPE-2, other track) already reads persistedOutputPath, so the journal body
is whole on the base used here. Recall still gave "" after compaction: the 222 KB row is larger than
RECALL_BUDGET_BYTES, pickRecall never cuts a row, so it skips it and nothing else scores. Step 4 fixes that.
